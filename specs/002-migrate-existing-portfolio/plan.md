## Phase 0: Outline & Research

**Status**: ✓ Complete

**Output**: `research.md` with migration approach decisions

**Key Decisions**:
1. Manual content conversion with validation rather than automated scraping
2. Extract metadata from existing READMEs; manually craft narratives incorporating PowerPoint/Excel insights
3. Use Git file history timestamps for publication dates
4. Keep large assets (Excel, PowerPoint, PDFs) in original locations with links; move only images
5. Extract tags from tech stack mentions + domain keywords
6. Three-level validation: Markdown syntax lint → build pipeline → visual inspection

**Rationale**: Projects have varied structure requiring human judgment for quality narrative extraction. Preserves original voice and insights while restructuring for new format.

## Phase 2: Task Planning Approach

**Status**: ✓ Complete

*This section describes what the /tasks command will do - DO NOT execute during /plan*

### Task Generation Strategy

The /tasks command will generate implementation tasks by:

1. **Load template**: Use `.specify/templates/tasks-template.md` as base structure
2. **Generate migration tasks**: One task group per project (5 projects × 10 steps each)
3. **Generate validation tasks**: Constitution update, final verification, documentation

### Task Categories

**Per-Project Migration Tasks** (5 projects × 10 steps = 50 tasks):

Each project follows the 10-step quickstart workflow:

1. Create directory structure
2. Extract publication date from Git history
3. Create `project.yaml` with metadata
4. Craft `narrative.md` from README/presentations
5. Copy image assets to `assets/`
6. Validate metadata schema
7. Sync to database
8. Build and preview
9. Complete migration checklist
10. Git commit

**Integration Tasks** (3 tasks):

1. Update constitution with migration workflow
2. Final build validation (all projects)
3. Documentation review and cleanup

### Ordering Strategy

- **Sequential per project**: Steps 1-10 must be completed in order for each project
- **Parallel across projects**: All 5 projects can be migrated simultaneously (marked [P])
- **Final tasks sequential**: Constitution update → validation → documentation

### Estimated Task Count

- Migration tasks: 50 (5 projects × 10 steps)
- Integration tasks: 3
- **Total: 53 tasks**

### Validation Approach

Each project passes through 6 validation gates (per `contracts/migration-validation.md`):

1. File structure validation
2. Metadata schema validation
3. Narrative content validation
4. Database sync validation
5. Build pipeline validation
6. Visual inspection

Feature completion requires all 5 projects passing all 6 gates.

### Success Criteria

- All 53 tasks completed
- All 5 projects synced to database (total project count: 7)
- Build succeeds with `--validate` flag
- Constitution updated to version 1.1.0
- All migration checklists complete
